## Summary

* Original classes: 101 (27 are healthy-leaf classes by name); images 2,263; after removing 43 duplicate/conflict images: 2,220 usable.
* **Primary cohort = 75 classes** with >= 13 usable images; **26 classes are outside the primary evaluation** (7-12 usable images).
* Why 13: Protocol A needs 3 query + 10 gallery images per class; Protocol B needs 3 test + 2 dev queries and a train/gallery split of the rest with >= 4 train and >= 5 gallery positives per class. Classes below 13 cannot supply disjoint train/gallery/dev/test sets, so they were not evaluated in the primary protocols.
* Primary classes: usable images min 14, median 24, max 67; excluded 26 classes: min 7, median 10, max 12.
* Healthy classes inside the primary cohort: 25 of 27 (the other 2 healthy classes are in the excluded set).
* The ~0.80 Hit@1 result is **a 75-class closed-set result** (Protocol B/C galleries contain only the 75 primary classes). It is not an evaluation over all 101 classes.
* The 26 non-primary classes were only used in Protocol A's *secondary* cohort (1 query per class, training-free baselines) and are never seen by the trained models of Protocol B.

## Feasibility of an all-101-class evaluation

* Evaluating retrieval over all 101 classes **without a trained component** is possible (frozen features; the classes in the excluded set have 7-12 usable images, so queries would be 1-2 per class and recall/AP ceilings are tiny; CIs would be very wide).
* A **trained** system cannot be evaluated on the 26 excluded classes with a leakage-controlled train/gallery/test protocol: a class with e.g. 4 usable images cannot give a train, gallery and test image that are also group-disjoint. Using them only as gallery/query distractors (open-set) is feasible and would test false-match behaviour, but it is a different question from closed-set Hit@1.
* Therefore a fair 101-class number would need either more data for the 26 classes or a separate open-set protocol; it should not be merged with the 75-class headline.
